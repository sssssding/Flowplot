# 专业复核与独立验收实施计划

日期：2026-10-13；负责人：Codex（流程准备）。本文件是待执行计划，不是验收结果，也不指定或冒填专业审核人。

## 三类工作分开记录

1. 工程对照：逐文件检查 GUI 与 API 的选择、模式、符号、单位及保存解来源；编码代理可以记录实际看到的内容。
2. 专业复核：具有相应经验的团队成员审核建模意图、标签、严重等级与物理适用性，填写真实审核人、日期和依据。
3. 独立验收：未参与规则调试的人员独立建立并冻结新模型和标签；开发集 GUI 一致或专业审核通过不使它变成独立集。

原六模型和 14 个受控变体始终是开发回归数据。禁止通过复制改名、轻改参数或随机拆分这些样本，宣称获得独立验收集。

## 开发集专业审核清单

每个模型先记录实际文件 SHA-256，并分别填写：

- 模型路径、COMSOL 版本、来源及是否保留求解数据。
- GUI 实际的组件、物理场、研究、启用节点、声明/有效边界和相关表达式/单位。
- 原工程预期 code；专业审核结论采用“同意 / 需修订 / 证据不足”，不能只写“通过”。
- 每个问题的严重等级、定位、解释与建议是否合理；有不同意见时写明依据。
- 审核人、真实日期、剩余问题和证据位置。尚未审核时这些字段留空，不填写 Codex 为专业审核人。

重点：默认全边界壁面被入口/出口替代不是同时有效的冲突；负法向流入速度是意图待核对项；以高度 H 计算的 Re 及默认阈值 2000 是团队筛查约定，不是普适转捩结论。

基准另外审核发展区、壁面、入口实际流量偏差、质量守恒阈值及网格影响。看见近似抛物线曲线不等于完成网格无关性或全域充分发展验证。

## 独立模型集的准备与冻结

- 模型建立人/专业标签审核人应未参与本轮规则调试；实际人选由团队确定。代码评审者不自动获得专业审核身份。
- 首轮准备至少 10 个此前未用于开发的模型。先保持当前已验证模板：二维、单域、轴对齐米制矩形、稳态牛顿层流、材料来源明确、法向入口/压力出口/No Slip 壁面。
- 覆盖首批五个规则，并包含至少一个无预期问题的负对照。应有不同独立建模来源和工况设计；数量或文件哈希不同不能证明独立性。
- 文件名使用中性 case ID；专业人员先核对 GUI 并锁定标签，不能先看程序输出再改标签使之命中。
- 原始 MPH 按 Git LFS 管理，未经授权的数据不上传。模型、标签和规则/解析源码在正式评估前分别冻结提交及 SHA-256。
- 独立验收期间不调规则。若根据结果修改实现，此集转为已使用数据，重新准备未参与调试的验收集。

范围外模型、坏报告和部分检查可单独组成鲁棒性检查组，不能混入正式支持范围集后只挑成功样本引用高 Recall。也不能为提高成绩而事后静默排除失败项。

## 正式清单与执行

只有实际模型建立且完成专业审核后，才创建 `case-manifest-0.1` 验收清单，填写 `independent_acceptance_set: true`、`label_status: "expert_reviewed"`，以及每个 case 的实际模型哈希、审核后的 `expected_codes`、真实 `reviewed_by` / `reviewed_date`、`used_for_rule_development: false`。

本计划不附带填好这些字段的“示范验收集”，避免模板被当成真实审核证据。元数据仍是声明，软件不能自动认证审核身份或独立性；团队需保留来源及过程记录。

执行现有入口，输出目录必须全新：

```powershell
python -X utf8 src/flowpilot/check_suite.py --manifest '<已审核清单>' --model-root '<独立模型根目录>' --comsol-root '<COMSOL_ROOT>' --output-dir outputs/acceptance/run-001 --loads 2
python -X utf8 src/flowpilot/check_suite.py --manifest '<已审核清单>' --reports-root outputs/acceptance/run-001 --output-dir outputs/acceptance/offline-001
```

报告同时记录总案例数、完整检查覆盖率、未评估标签数、漏报/误报、模型级完全匹配比例、逐规则和 micro 指标，以及保守 Recall 下界。没有正例时 Recall 为 null，不记作 100%。保留所有失败、部分、超范围及来源不符记录。

当前工具的计分单位为模型 × code，不评估严重等级、边界定位或解释质量。这三项必须单独人工记录。严格 Recall > 90% 的字段通过，也不等于误报率、可用性或全部项目验收通过。

## 新用户界面试用

- 参与者未参与开发；记录实际参与者和准备条件，不用编码代理的操作时间代替。
- Python、依赖、COMSOL 许可与模型事先可用；从打开入口、选择模型开始，直到能正确说明问题、证据、建议和支持范围结束。
- 记录真实总耗时、误解、失败步骤及是否需要帮助，目标为 5 分钟内完成。程序后台耗时只是其中一部分。
- 至少核对正常、Critical、Warning，以及失败/部分/超范围的理解；没有触发规则不等于物理通过。
