# 离线协作报告包

动机：给队友看检查结论时，不应连同原模型、只读检查副本、运行日志和本机请求一起发送。新入口导出独立的可阅读、可重新导入的报告文件夹，不联网、不自动发送、不调用 COMSOL 或求解器。

## 桌面操作

1. 完成一次检查，或用“读取已有报告”打开单模型报告。
2. 点击窗口底部“导出协作报告…”，阅读敏感信息提示并确认。
3. 选择保存位置；工具新建 `report-package-<随机标识>`，不覆盖已有目录。
4. 审阅 `report.md`、`overview.txt` 和 `diagnosis.json`，再自行压缩**整个文件夹**发送。不要只发送单个文件。
5. 队友解压后可直接阅读 Markdown/文本；在安装项目 Python 依赖的桌面入口点击“读取已有报告”，选择解压后的报告包目录，即可查看诊断和概览，不需要源模型或 COMSOL 许可证。

报告包不是新的模型检查。“部分检查未完成”和“超出范围”原样保留，旧报告缺少的加载次数、配置或来源证据不补造。旧报告没有概览证据时，文本明确显示概览不可用。

## 命令行

```powershell
python src/flowpilot/report_package.py outputs/check-suites/overview-verified/missing_inlet --output-dir outputs/shared/missing-inlet-001
```

输入是含 `run.json` 和 `diagnosis.json` 的单模型检查目录，而不是批量汇总根目录。输出必须不存在，也不能位于原报告目录内部。返回 0 表示导出完成；1 表示验证或写入失败。

## 文件和完整性

固定只有以下六个文件：

- `diagnosis.json`：保留原诊断全部内容，重新序列化为 UTF-8。
- `run.json`：仅保留源文件名/哈希、完成状态、诊断指纹，以及原记录中有效的已知版本/源码指纹/时间/重复加载次数/Re 阈值字段。
- `report.md`：重新生成中文诊断与建议，不复制原目录的 Markdown。
- `overview.txt`：从已验证的诊断生成模型快照概览。
- `README.md`：接收方操作和隐私说明。
- `package.json`：前五个文件的大小与 SHA-256、导出时间及原 run/diagnosis 文件指纹。

重新导入时先检查清单版本、固定文件名、大小、指纹，再按普通报告核对完成状态和诊断来源；任一文件改变、缺失、额外文件或链接均拒绝。单文件上限 10 MiB，不递归查找、不执行包内文件、不自动解压。对比入口也复用此核验，保留的来源字段允许同配置的原报告和导出报告进行离线对比；证据不足时仍阻断比较。

清单与完成元数据另外限制为 64 KiB；最终报告采用 [严格 JSON 与共同核验](REPORT_VALIDATION.md)。刚刚核对过的字节直接用于解析、对比/导出来源指纹与批量评估，不另读可能已经变化的文件。批量入口也不能绕过包内 Markdown 等文件的完整性检查。

完整性清单不是数字签名：它检测意外损坏，不证明作者、数据真实性、独立验收资格或物理正确。自行重写全部哈希的人仍可伪造内容。包不是求解结果文件，不包含 MPH，无法靠它恢复 COMSOL 模型。

## 隐私和失败处理

不复制 `.mph`、模型读取清单、日志、请求、命令或本机路径元数据字段。白名单之外的设置也不复制。**不是全文脱敏**：模型文件名、材料参数、表达式、标签和诊断自由文本可能包含项目敏感信息甚至路径；请人工审阅后决定分享范围。工具不上传、不替用户发送。

所有内容准备好后才创建新目录，清单先写、完成记录 `run.json` 最后写；中途失败不发布可用的完整报告。失败目录保留供排查，不自动删除；不要分享，换新目录重试。原报告和模型不改动；导出失败不会清除桌面当前已经核验的结果。

## 验证与回退

离线测试覆盖往返、来源保留、隐私字段白名单、旧版/部分/超出范围报告、损坏和缺失文件、链接、大小限制、拒绝覆盖、路径越界、写入失败及窗口确认/错误流程。真实隐藏窗口测试使用本机新生成的缺少入口报告，实际触发导出按钮、重新导入并显示概览；修改中文报告后重新读取被拒绝。这不是人工可见界面试用或专业复核。

回退时移除桌面导出按钮及 `report_package.py` 的入口；既有普通单模型检查不变。保留 `package_integrity.py` 的包核验支持，已有协作报告仍可读取，不应移除校验后继续声称已验证报告包。
