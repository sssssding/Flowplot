# 正式验收结果的离线复核

日期：2026-10-13；入口 `acceptance_result.py`。配合 [验收集冻结](ACCEPTANCE_FREEZE.md)，从完整来源记录及单模型报告重算指标，不直接相信保存的 Recall 数字。

目前尚无团队实际专业审核的独立模型集。本轮流程测试使用明确标记的模拟模型字节/诊断/审核声明，不代表完成真实独立验收，不能引用其分数作为项目成绩。

## 如何使用

```powershell
# 对真实检查运行复核：自动使用该运行自己的 checks 子目录
python -X utf8 src/flowpilot/acceptance_result.py outputs/acceptance/run-001 --dataset outputs/acceptance/frozen-001

# 对原离线评估运行复核：必须再次指定实际单模型报告目录
python -X utf8 src/flowpilot/acceptance_result.py outputs/acceptance/offline-001 --dataset outputs/acceptance/frozen-001 --reports-root outputs/acceptance/run-001/checks

# 核验后另存中文报告与 JSON（新目录，不能在原运行/冻结集/报告根目录内）
python -X utf8 src/flowpilot/acceptance_result.py outputs/acceptance/run-001 --dataset outputs/acceptance/frozen-001 --output-dir outputs/acceptance/review-001
```

入口不调用 COMSOL、不启动 UI、不修改模型或原始结果。读取冻结集需要检查模型副本哈希，因此应保留完整冻结目录；不能只保留成绩 JSON。

退出码 0 表示完整结果成功核验，**不表示 Recall 达标或全部项目验收通过**；2 表示可复核但检查覆盖不完整，不能作为通过结论；1 表示无效、损坏、来源不符或读取/导出失败。Recall 目标是否满足在报告中另行呈现，误报、严重等级、定位、解释、物理与新用户试用仍需独立审核。

## 核验内容

1. 顶层必须有 `acceptance-run-0.2` 的 completed/incomplete 记录及带开始/结束时间的完成元数据；failed、cancelled、running、缺记录或旧版无绑定结果拒绝。
2. `run.json` 绑定 `result.json`、`checks/run.json`、`checks/summary.json` 的字节指纹。正式发布时核对批量返回值与保存汇总一致，完成状态/案例数/来源/阈值一致；结果写入后再核对快照，不用变动后的文件冒充内存返回值。
3. 正式结果与冻结标记、数据集 ID、冻结标签、程序和登记指纹必须一致；读取前后再次核对冻结集。元数据/结果/批量文件解析和哈希来自同一次字节读取，不解析后另读文件计算来源指纹。
4. 对真实检查只读该运行自己的单模型报告；离线模式显式指定原报告根目录，不记录或猜测原本机绝对路径。单模型目录链接/目录联接拒绝。
5. 每个单模型报告复用共同读取核验，包括完成状态、源码/配置/模型哈希、必要条目和报告包完整性；已有问题条目不因格式缺失而静默补造。
6. 以冻结清单重算模型×code 口径的 TP/FP/FN、Precision/Recall/F1、覆盖率、漏报/误报、逐模型匹配、逐规则指标、保守下界及验收资格；同时核对案例顺序、诊断/运行指纹。布尔值不能冒充数值，重排、删项、改分数或重新绑定摘要哈希不能绕过重算。

这些检查防止不一致的记录被正常读取，不是作者签名、可信运行证明或文件系统级原子快照。拥有文件权限的人仍可同时重写所有输入、诊断和哈希；软件不能证明 COMSOL 确实执行、审核人真实、专业标签正确或数据独立。

[批量发布保护](BATCH_STABILITY.md) 新增的可选 `summary_sha256` / `input_stability_verified` 存在时须核对实际汇总字节和严格 true；可选 `source_fingerprints` 须与冻结记录一致。外层哈希重新绑定不能绕过；旧匹配格式中缺少这些可选字段时不自动补造稳定性证明，仍按原逐报告重算要求核验。读取器与批量源码指纹均变化，不手改历史冻结记录升级。

## 不完整结果如何呈现

- partial / unsupported 诊断仍核对其内容和运行指纹，但不作为完整模型计分，不因为其他模型 Recall 高就改成通过。
- 无完整诊断的 failed / unscored 案例保留不计分；编译/启动失败可能没有单模型完成文件。报告明确列出不能完整认证原失败原因/历史文件状态的案例，不拿缺失结果当正常负例。
- 原来失败但后来补上报告，不能直接套用旧汇总；状态或可计分证据不符会拒绝。修复后应新建运行，不能改旧统计。
- 原失败原因可能含本机路径，并非计分输入；复核按计分结构比较，不要求错误文字在不同电脑完全一致。导出摘要不复制该原因文字，也不复制模型、日志或审核人自由文本；数据集 ID / case ID 等仍需分享前审查，不能当全文脱敏。

## 文件格式与旧版本

冻结格式仍为 `acceptance-freeze-0.1`，新增复核程序也纳入冻结源码指纹；旧冻结目录若源码不匹配，不静默升级或手改哈希。正式运行/结果改为 `acceptance-run-0.2` / `acceptance-result-0.2`，缺少结果/批量绑定的旧记录保留历史，不作为新入口可复核成绩，需由团队按当前流程重新运行。

另存目录只包含 `review.json` / `report.md`，不是原正式运行目录或签署证书，也不能替代所引用的冻结集与单模型证据。Markdown 转义自由文本和 HTML，未执行任意嵌入内容。中途导出失败可能留下不完整目录，工具不会覆盖或清理；重复操作用新的目录。

若需让接收方在没有原电脑目录的情况下独立重算，使用 [正式验收证据交接包](ACCEPTANCE_BUNDLE.md)。该入口需显式确认复制模型，包含冻结 MPH、审核声明及原始证据，不是本节的轻量摘要或全文脱敏报告；接收方只读核验，无需调用 COMSOL。

## 验证与回退

本轮新增 20 项结果专项及 3 项发布保护测试。测试模拟模型读取，实际执行冻结、正式编排、共同报告读取、重算与导出；明确不使用 COMSOL 或独立物理模型。覆盖错误计数/分数（即使同时更新哈希）、报告缺失/改动、错冻结集、版本/状态、写入失败、部分结果、来源快照、JSON 限制与转义等。

原六模型上一轮真实报告另经通用入口离线复核，仍为 6/6 匹配；本轮未重新求解、未修改既有诊断规则或桌面代码，不能把这六份开发报告当作正式独立成绩。

回退需同时恢复正式发布格式及相应测试；不只删除读取器后修改旧记录中的版本号。原模型、通用检查、批量与桌面入口不受新增复核模块独立撤回影响；冻结指纹变化需按团队流程重新确认，不能自动提升历史结果。
