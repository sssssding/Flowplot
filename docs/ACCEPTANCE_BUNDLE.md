# 正式验收证据的离线交接包

日期：2026-10-13。入口 `acceptance_bundle.py`，配合 [验收集冻结](ACCEPTANCE_FREEZE.md) 与 [正式结果复核](ACCEPTANCE_RESULTS.md)。接收方只依赖包内冻结模型和原报告即可重算，不依赖发送方电脑上的绝对路径。

团队目前没有真实专业审核的独立模型集，因此尚未生成真实正式验收包或独立成绩。专项测试使用明确标记的模拟模型字节、诊断和审核声明，不能把测试输入当成独立物理模型。

## 分享前确认

此包与 [轻量单模型报告包](REPORT_PACKAGE.md) 不同，**包含全部冻结 MPH、审核人/来源声明及正式结果元数据**，不是脱敏摘要。模型参数、自由文本及失败记录可能含敏感信息或本机路径。须先确认模型共享授权并人工检查内容，再自行分享；命令要求显式 `--include-models`，不会上传或联系队友。

若只需要让队友阅读问题解释，用轻量报告包；若只需要查看汇总，用 `acceptance_result.py --output-dir` 导出摘要。它们均不能单独替代正式验收重算所需的全部输入。

## 发送方导出

以下目录仅为用法示例，必须先有团队真实审核、冻结并运行的记录；不会自动生成验收数据。每次使用新输出目录，不能放在原运行、冻结集或原报告根目录内。

```powershell
# 对真实 COMSOL 检查记录打包，使用该记录自己的 checks 报告
python -X utf8 src/flowpilot/acceptance_bundle.py export outputs/acceptance/run-001 --dataset outputs/acceptance/frozen-001 --output-dir outputs/acceptance/bundle-001 --include-models

# 若正式记录来自离线评估，必须显式给出当时评估的单模型报告根目录
python -X utf8 src/flowpilot/acceptance_bundle.py export outputs/acceptance/offline-001 --dataset outputs/acceptance/frozen-001 --reports-root outputs/acceptance/run-001/checks --output-dir outputs/acceptance/bundle-offline-001 --include-models
```

导出先复核原记录，再复制允许的文件，并分别复核副本和原输入；变化、不一致或复制错误拒绝发布。输出不覆盖、不自动清理；失败可能留下部分目录，应保留排查或自行处理，下次使用新目录。`bundle.json` 最后写入，是否有效仍须运行 `verify`，不能仅凭文件存在或 `ready` 字样判断。

## 接收方核验

将整个目录原样复制到接收方电脑，使用匹配的项目源码及 Python/项目依赖：

```powershell
python -X utf8 src/flowpilot/acceptance_bundle.py verify 'D:\received\bundle-001'
```

核验只读文件，不启动 COMSOL、不求解、不需要 COMSOL 许可证，也不启动桌面 UI。先检查清单、边界与字节完整性，再从包内冻结标签及单模型诊断重新计算计数、覆盖率和指标，最后再次检查完整性；中文输出与包内摘要必须一致。

退出码 0 表示完整记录成功核验，**不是 Recall 达标或全部比赛验收通过**；2 表示有效但不完整的记录，仍不能作为通过；1 表示损坏、来源/版本不符或操作失败。partial、unsupported、失败或无报告的案例不会在交接后变成完整负例；原失败原因不能完全认证的限制也保留。

## 包含哪些文件

- `dataset/`：原冻结标记、标签清单及全部冻结模型副本，保留原字节。
- `run/`：正式 `run.json` / `result.json` 和批量运行/汇总。真实检查模式还包含自己的逐模型证据；离线评估模式将实际使用的证据放在包内 `reports/`。
- 普通单模型目录仅复制存在的 `run.json` / `diagnosis.json`。若原输入是带 `package.json` 的单模型报告包，则验证并完整保留全部六个文件，不拆包绕过原内部校验。
- `review.json` / `report.md`：从证据重算的结构化及中文摘要；`README.md`：分享提醒；`bundle.json`：文件尺寸、指纹、来源绑定及工具版本。

不复制检查时的模型快照、请求、模型清单导出、编译输出、许可证文件或日志；已包含的模型/审核/失败元数据也不承诺全文脱敏。只分享 `review.json` 无法让队友独立重算。

## 完整性边界与限制

仅支持固定目录格式 `acceptance-bundle-0.1`，不自动压缩或解压归档。允许的路径和实际文件/目录须完全一致；链接、目录联接、路径穿越、额外文件及额外空目录拒绝。清单最多 256 KiB、512 个载荷文件、1024 个目录项；单模型最多 512 MiB、载荷合计最多 2 GiB；元数据通常最多 64 KiB，其他 JSON/文本最多 10 MiB。超限请由团队调整方案，不拆散文件或手改清单绕过。

冻结程序/登记版本继续按原冻结指纹核验，打包工具另外绑定自身源码 SHA-256。接收方需使用相匹配的代码；不要手改旧包指纹来适配新版本。JSON/模型等按二进制原样传输，不重新保存或经 Git 换行转换；中文生成摘要使用 UTF-8/LF。

这些检查可发现损坏、遗漏及不一致，**不是作者签名、可信执行证明或文件系统原子快照**。有权限的人仍能同时伪造全部模型、标签、诊断和哈希；软件不认证专业人员身份、标签正确性、真正独立性或实际 COMSOL 执行。真实专业审核和新用户试用仍由团队完成。

## 测试与回退

19 项专项测试覆盖显式确认、换目录后原输入不可用、真实/离线模式编排、原单模型包保留、缺失/篡改、重新绑定摘要仍拒绝、部分结果、大小限制、链接与 JSON 边界、复制/标记写入失败和命令退出码。所有正式集流程使用模拟输入，不是新的真实 COMSOL 验收。

本模块是独立交接入口，未修改诊断规则、模型解析或桌面流程，也不纳入冻结规则源码集合；撤回模块及其测试/文档不改变原冻结/复核流程。打包工具自身变化会使已有包的工具版本核验不匹配，应使用原匹配版本复核，不能静默升级记录。
