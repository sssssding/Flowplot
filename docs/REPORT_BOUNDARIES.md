# 报告目录边界与输入保护

日期：2026-10-13。修复共同读取器先解析路径而可能跟随报告根目录链接，以及通用/正式批量输出允许写入输入报告树的问题。规则、Java 解析、原模型及诊断格式不变。

## 当前行为

- 共同读取器在 `resolve()` 前检查收到的报告根目录；符号链接或 Windows 目录联接拒绝。桌面读取、对比、历史、协作导出与批量评分不能因为目标内容格式正确就绕过目录边界。
- 协作包直接完整性读取入口也要求根目录为实际目录，不先读取链接目标的 `package.json`；原有包内文件链接、大小及完整性检查继续执行。
- 离线批量输入根目录必须真实存在且不是链接/联接。单个案例目录是链接时不读取目标、作为 unscored，其余实际目录继续检查，整组不完整。
- 批量每例前及发布前后重新检查输入根目录。运行期间根目录消失或成为链接时失败停止；已计分案例后来成为链接也由发布保护拒绝，不继续套用旧汇总。
- 通用批量输出必须是新目录且位于输入报告根目录之外，路径解析后的目标也不能落入输入树；现有/断裂的输出链接或联接拒绝。
- 正式运行在创建外层目录之前检查报告根目录及输出位置，不等后端拒绝时才留下输入树内的失败目录。共用的新输出检查也拒绝断裂联接。

普通报告和完整协作包放在实际目录中仍按原格式读取。不移动、复制、删除或“修复”链接目标；若之前依赖链接路径，请自行确认真实目录并选择实际路径。当前变化是目录政策，不是标签、等级或物理判定变化。

## 为什么不能嵌套输出

批量输出包含 `summary.json` / `report.md` / `run.json`。放进待复核目录便写入了输入树；若输入是严格文件清单的协作包，还会因新增目录破坏完整性。现在在创建输出与读取案例前拒绝这些选择，输入文件保持不变。

```powershell
# 输入与输出为平级目录；每次输出目录必须不存在
python -X utf8 src/flowpilot/check_suite.py --reports-root outputs/check-suites/team-001 --output-dir outputs/check-suites/team-001-review
```

开始前目录不合法是入口错误（CLI 1），稳定的案例链接/无效报告导致覆盖不完整（CLI 2），运行中目录改变则 failed（CLI 1）。不能凭中间汇总存在判断成功，见 [批量发布保护](BATCH_STABILITY.md)。

## 保证范围

检查收到的根目录、批量根目录与直接案例目录，以及原有普通文件读取边界；不是操作系统级文件访问沙箱或全盘祖先链接审计。其他程序仍可能在检查与打开之间替换路径，没有使用目录句柄实现原子快照/排他锁，也不认证路径历史、报告作者或物理正确性。

本轮改动的 `desktop_session.py`、`package_integrity.py`、`check_suite.py`、`acceptance_dataset.py` 均在正式冻结源码集合中；旧正式记录应使用匹配版本或由团队重新确认，不能手改哈希升级。模型参数、失败日志和人员信息的隐私审查要求不变。
