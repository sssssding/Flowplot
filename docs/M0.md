# M0：模块化诊断与报告兼容

本阶段只迁移已验证的二维平面流动检查，建立按实例调度、局部覆盖和版本化报告。轴对称、传热规则及三维仍分别属于 M1、M2、M3；真实创建热接口或流热耦合只用于验证采集及跳过边界。

## 运行链路

`ModelInventory.java` → `inventory-0.2` → `diagnostics.py` 调度 → `diagnostic_modules` 简单注册表 → `diagnosis-0.2` → 统一报告读取、桌面、导出、批量与推荐。

现有 `normalize`、`validate`、`check` 保留为旧流动投影的兼容入口。流动实现迁入独立模块；调度器按物理场类型查询注册表，不在 UI 中添加逐物理场分支。M0 只登记 `LaminarFlow`，不预建热规则、动态插件或远程服务。

每个问题保留原规则 ID、等级、解释、节点、边界及数值证据，另带模块及组件/物理场/几何来源。实体编号只在其来源范围内有意义。覆盖记录包含物理场/耦合、适用性、`checked / skipped / unknown`、原因、规则依赖及指向原始 inventory 的 JSON Pointer。部分数值规则另记录节点级执行证据。

`run.json.status=completed` 与 `diagnosis.run_status=completed` 表示读取及诊断流程完成。诊断的 `checked / partial / unsupported` 另表示覆盖程度；`checked` 也可能发现严重问题。空问题清单与运行完成均不能代替覆盖判断。

## 支持与跳过

| 输入/证据 | M0 行为 |
|---|---|
| 原二维矩形单域牛顿流体、定常研究及已核验边界模式 | 运行原规则，保留原判定及证据 |
| 既有平面边界模板 | 保留边界检查；没有已核验特征尺度时跳过 Re 并显示部分检查 |
| 未登记的物理场 | 单独记录未知；保留其他满足前提的流动结果 |
| 活跃或启用状态无法确认的耦合 | 按全局/组件作用域阻断依赖流动语义的规则；保留独立成立的材料常数检查 |
| API 明确禁用且完整读取的耦合 | 明确跳过；其他活跃未知接口仍影响完整覆盖判断 |
| 不支持的维度、材料配置、边界模式或嵌套节点 | 记录该流动物理场的前提不足及具体原因，不将能力不足当作模型错误 |
| 缺失或不可求值的参数 | 保留表达式、单位、状态及采集原因；相关检查未完成，不代入零 |

M0 的材料正值判定仍以已确认的牛顿流体材料绑定为前提。未实现多域材料覆盖、热材料模型或任意手工耦合语义。未知耦合采取保守作用域阻断，不按节点名猜引用关系。

## 契约与旧数据

- 新报告使用 `schema/diagnosis.schema.json` 和额外的状态/来源一致性校验；覆盖或完整规则引擎指纹缺失时拒绝读取。
- 旧 `diagnosis-0.1` 报告继续按旧路径读取，不补造模块覆盖。旧归一化模型维持 `diagnostic-0.1`，使旧训练数据保持可读。
- 推荐只接受原矩形单流动物理场范围；现代报告有未知、多物理场或部分检查时明确拒绝。训练数据、模型和历史测量不升级、不重写。
- 报告对比要求契约、引擎、读取器、COMSOL 和设置一致，部分报告不推断问题消失。新问题分组包含模块及实例来源。
- 批量只给完整 checked 报告计分；正式冻结保存所有新增模块及契约指纹。旧报告可以阅读，但不冒充当前引擎生成的批量证据。
- 新 `rule_engine_sha256` 是包含调度器、流动模块、注册表、指纹算法及两个 Schema 的确定性聚合值。历史字段保留原含义；正式结果根据冻结源码清单选择对应算法。

历史证据不变，原来源固定在 `890af06`。旧实测测试核验固定来源清单；本轮另生成绑定当前源码的 M0 实测摘要。起点审计、原有五项差异及回退方式见 [M0_BASELINE.md](M0_BASELINE.md)。

## 验证入口

先运行完整离线测试，再运行真实 COMSOL 的六模型检查及 API 探针，最后执行消费端与历史回归核验。每个输出使用新目录。

```powershell
python -X utf8 -m unittest discover -s tests
python src/flowpilot/check_suite.py --comsol-root '<COMSOL_ROOT>' --loads 3 --output-dir outputs/m0/real-six-final
python scripts/verify_m0_api.py --comsol-root '<COMSOL_ROOT>' --write-fixture
```

`verify_m0_consumers.py` 使用新六模型报告和实测 API 清单，在隐藏 Tk 窗口中检查显示、来源定位、历史、报告对比、包往返与推荐边界；`verify_m0_regression.py` 对比原基线实现与当前实现，区分新读取的六模型和历史十四变体清单回放。这些是工程测试，不代替本阶段的人工作品验收。

真实 API、许可与采集字段说明见 [M0_API.md](M0_API.md)。本机完整日志与模型副本位于忽略目录；可共享摘要单独保存在 `data/fixtures/m0_*.json`。
