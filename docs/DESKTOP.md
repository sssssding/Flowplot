# 本地桌面检查界面

第一版桌面入口将现有“选择模型—只读解析—中文诊断”串起来，不修改原始模型，不运行求解器，不上传模型或连接网页服务。当前仅支持已经验证的二维、单域、轴对齐矩形通道稳态牛顿层流配置。

## 启动与使用

1. 确认已安装 Python（包含 Tcl/Tk）、`requirements-dev.txt` 中的依赖，以及有可用许可证和模块的 COMSOL 6.3。
2. 在 Windows 文件夹中双击项目根目录的 `FlowPlot.cmd`（旧 `FlowPilot.cmd` 仍兼容）。依次使用显式 `FLOWPILOT_PYTHON`、项目 `.venv`、系统 `python`；先检查依赖，缺失时给出配置提示，不自动安装或替换环境。名称约定见 [NAMING.md](NAMING.md)。
3. 选择一个已经下载完整的 `.mph` 文件；选择 COMSOL 的 `Multiphysics` 文件夹（其中应有 `bin/win64`），再选结果保存目录。
4. 点击“开始检查”，等候结果。默认重复加载 2 次，每个编译/读取进程超时 300 秒，Re 筛查阈值 2000；不是整个检查的总超时。
5. 点击问题行查看相关节点、边界编号、证据与建议；可打开结果目录或查看完整 Markdown 报告。

也可以用已有 Python 环境启动：

```powershell
python src/flowpilot/desktop.py
```

若 `.venv` 存在但依赖不完整，选择自己已经准备好的环境，例如：

```powershell
$env:FLOWPILOT_PYTHON = (Resolve-Path './.venv-tests/Scripts/python.exe').Path
./FlowPlot.cmd --check-env
./FlowPlot.cmd
```

示例中的 `.venv-tests` 是本机已有环境，队友应换成自己的可用环境；虚拟环境和解释器路径不提交仓库。`--check-env` 只检查 Python、jsonschema 和 tkinter 是否可导入，不创建窗口、不启动 COMSOL，也不证明许可证或可见界面通过。`FLOWPILOT_NO_PAUSE=1` 仅供自动化测试关闭失败后的控制台等待。

可选参数为 `--model`、`--comsol-root`、`--output-root`，只预填界面，不自动启动检查。也可用环境变量 `FLOWPILOT_COMSOL_ROOT` 预填安装目录；代码中不写死本机路径。

## 状态与结果

- “当前规则未发现问题”：当前模板内没有触发规则，使用中性色提示，**不是物理通过或专业验收通过**。
- “发现需要优先处理的问题”：至少有一项 Critical，需要先核对设置。
- “发现风险或待核对项”：风险提示，不武断宣称模型必然错误。
- “部分检查未完成” / “超出当前支持范围”：不能当作正常模型；阅读原因并人工处理。
- 失败或取消：不展示新的诊断结论；发起新检查时会清除旧结果，避免误看上一份正常报告。

窗口使用独立后台 Python 进程运行现有只读入口，并通过事件循环轮询状态，不在窗口事件处理器中等待 COMSOL。进度条是不确定时长的活动提示，不是计算完成百分比。

初始窗口按屏幕尺寸留出边缘空间；问题表格与证据区之间的横向分隔条可上下拖动。条目较多时增大表格，阅读解释和 JSON 证据时增大下方区域；两区均可滚动，不把隐藏行当作没有问题。

运行中会显示当前阶段和已用秒数：创建副本、准备读取程序、COMSOL 读取模型、规则检查与报告生成、核验完成记录。用时来自单调时钟，不因系统时间调整而倒退。`progress.jsonl` 仅提供提示；即使其中出现 `completed`，也必须等后台退出并验证 `run.json` 和诊断内容，才展示结果。旧报告没有进度文件也仍可读取。

## 查看模型概览

结果区有“问题诊断”和“模型概览”两个页签。概览显示报告中的通道尺寸、材料表达式/单位/求值、启用边界节点的声明选择与实际生效选择、入口速度和出口压力。不额外调用 COMSOL，也不能当作实时模型树或物理通过结论。

旧报告缺少模型证据、超出模板或证据结构不符时，明确显示概览不可用；未求值参数不填 0。新检查会清除旧概览。缺少入口/出口的诊断现在还带有启用节点与选择证据。详情见 [模型概览](MODEL_OVERVIEW.md)。

## 取消与关闭

点击“取消检查”后，界面向本次会话写入取消请求，后台停止自己启动的编译/COMSOL 进程树，并记录 `cancelled`。不会按进程名批量结束其他 COMSOL 会话。

运行中关闭窗口会先询问；确认后等待本次检查退出再关闭。非常接近结束时的取消请求可能晚于结果完成，此时已完成且经过校验的结果保留。若本机或窗口进程意外崩溃，应检查运行记录；不能把遗留文件当作成功报告。

若取消请求无法写入，界面会明确提示“检查仍在进行”，保持窗口和轮询，可重试或等待既定超时；不会假称已停止。若窗口运行记录无法保存或日志关闭失败，本次界面状态为失败、不展示结论，保留日志供排查，不覆盖已有记录。

## 读取已有报告

“读取已有报告”选择含 `run.json` 和 `diagnosis.json` 的**单模型检查目录**；批量结果要选具体模型子目录，不能选择整组汇总目录。无需 COMSOL 许可证即可读取报告。

界面核对成功完成状态、诊断文件内容哈希、诊断状态与源模型标识。不完整、被改动或旧版缺少来源字段的报告拒绝展示。只读入文件的完整性检查不证明报告签名、独立验收资格或物理正确性；批量评分仍使用 `BATCH_CHECK.md` 的额外源码与配置核对。

桌面、历史打开、对比、协作导出和批量使用 [共同报告核验](REPORT_VALIDATION.md)：必要条目字段不能缺失，checked 不能含未完成求值。最终元数据上限 64 KiB、诊断上限 10 MiB，拒绝重复字段、非有限数值和过深 JSON；解析与指纹来自同一次读取。旧报告没有可选模型快照时仍可读，不会补造概览。

## 对比前后两份报告

先检查或读取**本次**报告，再点击“与前次报告对比…”，选择**前次**单模型报告目录。独立窗口展示新增、未再报告、证据/等级等变化和相同条目，支持另存为中文报告与 JSON，不运行 COMSOL。

规则/读取源码、COMSOL 版本、模板或 Re 阈值不同，以及部分检查/超出范围时，不给出新增或消失结论。“本次未再报告”不等于修复成功；两边模型的关联关系仍须人工确认。操作与计数口径见 [报告对比](REPORT_COMPARISON.md)。

## 检查历史

窗口底部“检查历史…”可浏览当前结果目录中的既往检查，支持切换目录和刷新；完成、失败、取消、未确认和无效记录分别展示。选择完成记录后点击“查看报告”，重新核验并显示到主窗口；其他记录可查看详情和打开日志目录。列表里的“完成记录”不等于报告已核验或模型通过。

后台扫描有目录项和文件大小上限，不递归查找，不读取模型，不跟随链接，不上传或清理文件。操作与状态边界见 [本地检查历史](CHECK_HISTORY.md)。

## 本机输出与隐私

窗口底部“导出协作报告…”可把当前经过核验的报告导出为独立文件夹。确认隐私提示后选择保存位置；队友可离线阅读，或解压后用“读取已有报告”重新查看。报告包不带模型/日志和本机路径元数据字段，但诊断自由文本和参数仍需人工审阅。导入时额外核对包内全部文件的指纹；哈希不是作者签名。详见 [离线协作报告包](REPORT_PACKAGE.md)。

默认输出在 `outputs/desktop/session-<时间>-<随机标识>/`，每次创建新会话，不覆盖原有报告：

```text
session-.../
  request.json         # 本机请求，含所选绝对路径
  launcher.log         # 后台入口日志
  cancel.request       # 仅取消时出现
  ui-run.json          # completed / failed / cancelled
  check/               # 原只读入口的模型副本、报告与日志
    progress.jsonl     # 只供阶段提示，不是完成凭证
```

这些目录被 Git 忽略。请求和日志可能含本机路径或软件信息，不直接上传。取消和失败时保留的副本、恢复文件及日志只供排查，不自动清理或覆盖任何原始模型。

## 影响与回退

本轮新增桌面入口与独立会话控制；单文件检查入口增加可选 `--cancel-file`，原有命令和 JSON 诊断契约不变。其他入口不传取消请求时仍使用原等待/超时流程。删除桌面启动器和界面模块即可回退界面；原 CLI、批量检查和模型保持可用。

若 Python 报找不到 Tcl/Tk 资源，应先在正常本地环境检查 Python 的 Tcl/Tk 安装；不要通过关闭 COMSOL 安全设置解决。当前开发隔离环境中的 Tk 资源访问受限，本机正常权限隐藏测试通过，未修改 Python 或 COMSOL 安装。

实现依据：[Python tkinter](https://docs.python.org/3.13/library/tkinter.html)、[subprocess](https://docs.python.org/3.13/library/subprocess.html)。
