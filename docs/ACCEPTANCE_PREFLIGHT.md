# 验收清单草稿的只读预检

日期：2026-10-13；入口 `acceptance_preflight.py`。面向实际准备清单的团队成员，在 [正式冻结](ACCEPTANCE_FREEZE.md) 前集中查看缺项，不再只能根据冻结入口的第一条错误逐项排查。

当前没有真实专业审核的独立模型集。此入口不生成示范验收数据、不填写人员/日期/标签、不复制或修改 MPH、不创建冻结目录，也不调用 COMSOL 或 UI。

## 使用

使用项目依赖所在的 Python，明确指定现有草稿清单及模型根目录：

```powershell
python -X utf8 src/flowpilot/acceptance_preflight.py --manifest '<待准备的清单.json>' --model-root '<模型根目录>'
python -X utf8 src/flowpilot/acceptance_preflight.py --manifest '<待准备的清单.json>' --model-root '<模型根目录>' --json
```

仅向标准输出打印中文待办或 JSON，不自动另存文件、不联网、不上传。草稿至少符合基本 `case-manifest-0.1` 结构（1–50 个案例，安全 ID、相对路径、不同模型哈希、有效预期 code 与阈值）；不是自由格式文档。结构错误先停止，避免读取无法安全定位的模型；有效结构中的审核/来源及逐模型文件问题尽量一并列出。

审核尚未完成时字段应留空或保持未审核状态。**不要为了让预检变绿而编造声明或修改开发集身份。** 预期标签需在看程序输出前由真实专业人员确定。

## 检查哪些准备条件

- 是否真实声明独立集、完成专业标签审核、达到至少 10 个案例；首批五条规则是否覆盖，并有负对照。
- 数据集和独立性审核声明的必填项、严格布尔值、已发生的标准日期。
- 每个案例的建立人、来源依据、审核人/日期、来源组及未用于规则调试声明。
- 至少两个来源组，大小写/首尾空格规范化后计算；不同组名本身不证明独立性。
- 已登记原六模型和 14 个受控变体的哈希不得混入正式集；未完成求值的鲁棒性标签单独处理。
- 案例 ID/模型路径的大小写重名、相对 MPH 路径、文件存在/普通文件、链接/目录联接、LFS 指针、空文件及与清单的 SHA-256 是否一致；一个文件错误不遮蔽其他案例。
- 复用真正的冻结校验作为最后门槛；准备提示不能降低正式入口的要求。捕获实际读取的清单指纹及程序/登记指纹，结束时重新检查这些来源是否变化。

只计算文件哈希，不证明字节一定能由 COMSOL 打开；真正的读取检查在冻结后的正式运行中执行。没有全目录原子快照，模型在读完后仍可能变化，因此预检不是冻结凭证，正式冻结必须重新核对所有输入。

## 状态与退出码

- `ready_to_freeze` / 0：当前文件与声明满足准备校验，可尝试正式冻结；不是身份认证、独立性证明、Recall 结论或全部验收通过。
- `blocked` / 2：清单可读但存在准备问题，或检查过程中来源变化。查看 `issues` 的字段、case ID 和中文原因，不自动修复。
- `invalid` / 1：清单不可读/基本结构无效，或程序/开发登记不可用，不能作准备判断。

JSON 格式为 `acceptance-preflight-0.1`，明确保存只读、未冻结、未完成正式验收及不认证审核身份的标志。模型的 `matches` 仅表示当前字节哈希匹配；其他状态分别显示缺失、哈希不同、无效文件、无法读取、危险路径或未检查。

报告不复制审核姓名、来源自由文本、数据集标题或异常中的绝对路径；case ID、模型哈希和固定源码路径仍可能敏感，分享前审查，不能当全文脱敏或签署证明。

## 当前实测与测试边界

对仓库现有六模型清单实际运行：6/6 文件哈希匹配，但整体为 `blocked`，共列出 54 条准备问题（含正式门槛总结项）。原因包括开发数据身份、数量不足、专业审核和来源声明缺项；不能把此清单补几个字段就当独立集。没有执行新 COMSOL 读取、求解或生成独立成绩。

23 项专项使用明确标记的模拟字节/审核字符串，覆盖多缺项、布尔/日期、全部文件错误、来源组/规则覆盖、路径/链接/JSON 边界、来源变化、最终门槛、隐私与 CLI 退出码。模拟“可准备”输入不是团队独立模型或专业审核证据。

这是独立准备入口，不改变诊断、模型解析、桌面或正式冻结的来源集合。回退时撤回新模块及对应测试/说明即可；既有冻结/复核格式与旧报告保持原有核验要求。
