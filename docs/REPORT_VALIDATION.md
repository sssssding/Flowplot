# 统一报告读取与核验

本轮不新增物理规则或扩大模型范围。目标是让桌面展示、历史重开、报告对比、协作导出和批量评估遵守同一份报告读取条件，防止格式不完整或状态矛盾的报告被当作完整检查。

## 原来的缺口

- 批量读取只提取规则 code，带有正确文件哈希的 `{"code":"REYNOLDS_RISK"}` 条目也会被接受，即使没有等级、解释、节点或证据。
- `status: checked` 同时含 `EVALUATION_UNAVAILABLE`，桌面会显示普通风险提示，而非拒绝矛盾记录。
- 批量入口没有复用协作包的全部文件核验；包内中文报告被改动而 JSON 没变时，仍可能继续计分。
- JSON 解析与指纹计算分两次读取；文件在两次读取之间发生变化时，解析内容和来源指纹不一定对应同一份字节。

这些反例是本地构造的损坏记录，不是新 COMSOL 模型，也不代表已有模型诊断均错误。

## 共同条件

读取经过界面无关的 `load_completed_check`；批量评估在共同条件之外仍核对清单模型 SHA-256、当前规则/模型读取源码和 Re 阈值。

- 完成元数据与诊断版本、状态、源模型标识及诊断内容哈希必须一致。
- 问题条目必须含已知 code、有效等级、文本解释、节点列表、正整数边界列表和对象形式的 evidence。重复问题条目仍保留，不悄悄合并。
- `checked` 不允许包含 `EVALUATION_UNAVAILABLE`；`unsupported` 必须有原因且没有问题条目。合法 `partial` 仍可读，但不能当作正常或完整检查计分。
- 旧报告缺少可选模型快照或模板字段时仍可读取，不补造缺失证据；缺少必要条目字段的旧/损坏报告应重新检查，不自动修复或升级状态。
- 批量不会利用 Python 中 `True == 1` 的行为接受布尔 Re 阈值；直接评估接口也拒绝声称 checked 却包含未完成求值的输入。

发现矛盾不等于能够判断哪一项正确。因此拒绝读取或记为 `unscored`，而不是自动把 checked 改成 partial、补上等级/证据或删掉不认识的条目。

## 有限读取与严格 JSON

`report_io.py` 对最终报告读取提供以下限制：

- `run.json` 和协作包 `package.json` 上限 64 KiB；诊断 JSON 上限 10 MiB。
- 协作包仍只有固定六个文件，每个产物上限 10 MiB；完成元数据另外受 64 KiB 限制。
- 每次读取最多取上限加一字节，不仅依赖读取前的文件大小；发现链接、目录或缺失文件时拒绝。
- 仅接受 UTF-8，可含 BOM；拒绝重复 JSON 字段、NaN/Infinity、指数溢出为无穷大的数字、异常编码及超过 64 层的对象/数组嵌套。
- 会话结束时读取最终状态也使用有限读取；坏元数据按失败收尾，不因递归异常中断轮询并遗留成功显示。

历史列表仍是有限元数据预览，不是诊断核验或进程存活判断；打开时重新走共同读取条件。进度日志也仍只是提示，不是完成凭证。

## 指纹与内容对应

普通报告的解析和哈希来自同一次读取的字节。协作包核对清单后，直接解析刚刚核对过的字节快照，不再次打开 JSON；对比、导出和批量元数据指纹也使用该快照，不另读磁盘计算来源。

这保证**所用指纹和所读内容对应**，不保证目录以后不变、多个文件有文件系统级原子快照，或下一次读取仍成功。文件随后变化时，下次打开会重新核验并拒绝不一致。哈希不是作者签名，不防止有人有意重写内容和全部指纹，不证明物理正确或独立验收资格。

## 验证与回退

```powershell
python -X utf8 -m unittest discover -s tests -p test_report_reader.py -v
python -X utf8 -m unittest discover -s tests -q
```

26 项新增专项测试覆盖共同拒绝路径、状态一致性、批量不可绕过包校验、重复字段/非有限数值/深嵌套/大小限制/BOM/链接、会话失败收尾，以及读取后磁盘变化时仍使用原快照指纹。测试编辑的都是临时合成记录。

使用上一轮六个真实模型的报告重新离线核验，模型与规则来源不变；另外重跑本机隐藏窗口的两次真实只读检查、取消、对比、历史和导出/重读。有效包可评估，改变包内中文报告后不计分；缺字段报告的拒绝验证单独标记合成输入，不当作真实模型或独立验收。

回退应整体恢复报告读取、消费者及对应测试，并重新验证，不宜只让批量入口绕过共同条件。普通模型检查和原模型不受读取格式加固影响；回退将重新引入缺字段记录计分及指纹/内容分离的已知风险。损坏或超限输入由用户在新目录重新生成，工具不删改旧文件。
