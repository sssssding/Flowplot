# 本地检查历史

检查历史用于找回过去的报告、查看失败或取消的记录，以及打开对应日志目录。不保存新的模型，不调用 COMSOL，不启动旧进程，不删除、修改或自动恢复任何历史文件。

## 使用

1. 启动桌面界面，设置“结果保存到”的目录。
2. 点击窗口底部“检查历史…”。默认读取上述结果目录，可在历史窗口另选目录、刷新。
3. 选择一条记录，查看模型、UTC 开始时间、来源哈希、阶段与错误详情。
4. 对完成记录点击“查看报告”：重新核验后显示到主窗口，之后可以使用前后报告对比。失败、取消、未确认或无效记录仅查看详情/打开目录，不开放诊断结论。

可读取两种布局：桌面输出目录下的 `session-.../check/run.json`，或批量输出目录下各模型子目录的 `run.json`。不是任意层级全文搜索；若选择 `outputs/` 总目录，应改选具体桌面会话根目录或一组批量结果。

无需 COMSOL 安装或许可证即可浏览历史。运行检查时不能新开历史窗口；若已有历史窗口，主窗口也会阻止打开历史结果覆盖正在运行的检查。

## 状态不是验收结论

- **完成记录（打开时核验）**：只发现完成元数据，尚未核验诊断文件；不表示模型无问题。
- **失败 / 已取消**：保留错误和日志入口，不展示遗留诊断。桌面运行记录显示失败时，即使后台有 `completed`，也不会当作可打开的完成会话。
- **运行中或中断，状态待确认**：磁盘没有最终记录、仅有 `running`，或后台完成但窗口还没有成功收尾；不能据此断言进程仍存活，也不会自动接管、停止或重新启动。
- **记录不完整或无效**：JSON、版本、来源字段或路径等存在问题；不会隐藏其他可识别记录。

打开报告时重新读取记录、检查路径、完成状态和诊断内容哈希。列表刷新后被改动、移走或重定向的报告可能被拒绝，此时保留主窗口原来的有效结果。核验遵循 `DESKTOP.md`；哈希不是数字签名，也不代替专业审核。

## 扫描边界与隐私

扫描在后台线程进行，不在窗口回调中等待磁盘 IO；关闭窗口后不会由迟到扫描结果操作已销毁的控件。仅检查所选目录下一层以及其中可选的 `check/`，每次最多查看 200 个目录项，单份元数据最多读取 64 KiB。不递归扫描工作区，不读取 `.mph` 或诊断正文，不跟随子目录、元数据或诊断文件的符号链接/目录联接。

超过上限会明确提示列表可能不完整，需要缩小所选目录。展示的记录按开始时间文本和标识倒序排列，但上限截断前的目录枚举不保证选中了最新记录；不把时间字段当作可信签名。

历史来自磁盘已有运行记录，不另建全局索引或保存用户设置，不上传路径、日志或许可证。详情可能包含本机路径，分享前仍需检查。

## 验证与回退

新增 22 项离线测试：空目录、两种布局、不读取模型/诊断、失败/取消/未确认状态、启动失败、元数据异常/过大、扫描上限、链接/越界拒绝、打开时重新核验、输入不变及关闭/扫描失败路径。

本机真实 COMSOL 检查后，隐藏窗口历史列表找到两条完成记录和一条取消记录；实际选择并打开缺少入口报告，取消记录的打开按钮不可用。证据见 `desktop_smoke.json` 的 `history_browser`。此验证不是可见界面、用户计时或专业验收。

实现仅增加历史发现模块、独立窗口和桌面按钮；不改变规则、诊断契约、模型或已有报告。撤回历史模块及桌面历史入口即可回退，原单模型检查、读取报告和前后对比仍可使用。
