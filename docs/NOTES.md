# 注意事项

## COMSOL 与模型

- 团队当前统一使用 COMSOL 6.3；基准模型和解析验证应在该版本下进行。
- 实验记录仍需注明具体补丁/构建版本、模块许可与 Java API 版本。
- 不依赖 GUI 中显示名称作为唯一标识；同时记录 component、physics 和 feature tag。
- 边界 ID 可能因几何重建改变，必须保存几何版本与人工对照表。
- 默认 Wall 也需要显式纳入解析验证，不能只读取用户新增节点。
- 原始表达式与求值后的 SI 数值分开保存，避免单位信息丢失。
- “超出范围”属于风险提示，除非有确定性物理或配置证据，否则不标记为错误。

## 数据与机器学习

- 数据集按“模型”划分训练、验证、测试集，禁止配置级随机切分造成泄漏。
- 保存每次求解的模型哈希、网格统计、配置、收敛状态、耗时、迭代次数和残差。
- 如果所有配置几乎都收敛且耗时接近，则数据不具备推荐价值。
- 推荐模型必须与 COMSOL 默认、人工经验和随机配置比较。

## 安全与合规

- 不提交许可证文件、服务器地址、用户名、访问令牌和私有模型。
- 赛事规则手册为项目参考资料；对外公开仓库前确认其再分发许可。
- 使用第三方模型或数据时记录来源、许可证和允许用途。
- AI 生成的物理解释必须由规则证据或实验结果支撑，并接受人工复核。

## 复现性

- 尽量使用相对路径和配置文件，不写死本机路径。
- 随机实验固定种子；运行环境和依赖版本纳入版本控制。
- 关键结果至少重复运行 3 次并记录波动。
- 自动生成内容不得覆盖原始模型；输出到独立目录并带运行 ID。
